# 08 · 后续开发方案（DeepSeek41）

> 基线：`v0.9.0-mvp`（提交 `897b6d1`）。核心加密与保险库能力已完成，本文覆盖**剩余业务功能**的开发计划、隔离与回溯策略。
> 功能进度现状见 `AGENTS.md` 的「功能进度」章节；对照清单见 `App功能总览-重构基线.md`。

## 1. 隔离与回溯

### 1.1 分支模型

| 分支 | 角色 |
|---|---|
| `main` | 稳定基线，停在 `v0.9.0-mvp`，只接受经完整验证的合并 |
| `DeepSeek41` | 本次接手的开发分支，全部工作在此进行 |
| `feat/<name>` | 可选：每个功能一个短分支，完成后合回 `DeepSeek41` |

- 每个功能完成打标签 `v0.9.x-<feature>`，可单独回溯或 revert。
- 单人开发也可直接在 `DeepSeek41` 小步提交，一个功能一个 commit。

### 1.2 工作树（可选，强隔离）

仓库路径含中文（`CC密码箱`），Flutter/Android 工具链对其敏感（`flutter analyze` 会崩、Gradle 拒绝非 ASCII 路径）。若需要**文件系统级隔离 + ASCII 路径**，用 worktree：

```
git worktree add ../vaultone-ds41 DeepSeek41
```

原目录留在 `main` 作回溯锚点，新目录在 ASCII 路径下开发，顺带绕开非 ASCII 工具链问题。代价：Rust `target/` 与 Flutter `.dart_tool/` 需重建。

### 1.3 回溯

- 任意时刻 `git checkout main` 或 `git reset --hard v0.9.0-mvp` 回到基线。
- 数据库 schema 变更**必须新增迁移**，禁止就地改旧迁移（`migrations/{sqlite,postgres}` 各一份）。

## 2. 质量门禁（每个功能合并前必须过）

- `cargo test --workspace`（当前 112 项）
- `cargo clippy --workspace --all-targets -- -D warnings`
- `dart analyze`（在 `app/` 下；勿用 `flutter analyze`，中文路径会崩）
- `flutter test`
- 改 UI 流程 → `flutter test integration_test -d windows`
- 改 `app/rust/src/api/**` → 重新 `flutter_rust_bridge_codegen generate`
- 改加密/协议 → 同步 `docs/01`、`docs/03`，跑 fuzz 冒烟

## 3. 工作分解

| E1 | **导出闭环** | `vault-core` 新增 export 模块；FRB `export_*`；UI 导出入口 | `.wljbak` 加密包 + CSV 明文；导出→导入往返一致；文件选择、进度、结果汇总 |

## 4. 建议执行顺序

E1（导出）→ E4（冲突）→ E7（备份卡）→ E5（模板）→ E6（分组/标签）→ E3（真机验证），P2（E8、E10~E12）并行启动。

理由：E1/E4/E7/E5/E6 纯客户端、无服务端依赖，可立即闭环；E3 依赖外部环境；P2 需先设计服务端协议再动手（E9 组织不做）。

## 5. 风险

- **schema 与同步兼容**：`ItemData` 加字段要过 `merge.rs` 三方合并与版本号，老客户端读到新字段需容错。
- **新域协议**：通知/组织/积分涉及新线协议，需先出接口设计（`vault-proto`）再实现。
- **Apple 环境**：iOS/macOS 相关在 Windows 上无法构建验证，列为阻塞项。
