# 14 · Android / iOS 局域网调试

> 本方案仅用于可信局域网和测试账户，不是生产部署方案。HTTP 不保护传输中的会话 Token、邮箱或反馈文本；保险库内容仍在客户端加密，但不能因此把开发 HTTP 当作安全公网服务。

## 1. 本机地址和服务端

2026-10-01 核对：电脑 WLAN 地址 **192.168.0.4**，端口 **9777**。手机应与电脑连接同一局域网，访问 `http://192.168.0.4:9777`。

- `127.0.0.1` 在真机上是手机自己，不是电脑。
- `198.18.0.1` 是当前 Meta 代理虚拟网卡，不用于手机连接；VPN/代理应让 RFC1918 私网流量直连，不要把局域网请求发送到远端代理。
- IP 可能随 DHCP 改变。换网后同时更新启动参数、Android Debug 的 `network_security_config.xml` 精确白名单及 `.vscode/launch.json` 的默认提示值。

`server/src/main/resources/application-dev.yaml` 已按本机联调配置：

```yaml
server:
  address: 0.0.0.0
vaultone:
  development:
    enabled: true
    allow-lan: true
    allow-test-kdf: false
```

保持默认 dev profile，在 IDEA 使用 Java 21 启动 `VaultOneServerApplication`。不要删除 `DeploymentGuard`：它现在仅在显式 `allow-lan` 时接受私网地址或 `0.0.0.0`，并禁止对非回环监听开放低成本测试 KDF。PG/Redis 连接仍必须在本机回环，不能跟着改成网卡地址或暴露端口。

开发来源过滤器只按实际 TCP 对端放行回环/RFC1918 IPv4（10/8、172.16/12、192.168/16），不相信 X-Forwarded-For。生产 profile 禁止 LAN 开关且继续强制 TLS。无需 CORS 设置：Flutter 原生应用不是浏览器页面。

## 2. Android 真机

本仓库含中文路径，Gradle 构建需通过无中文路径映射。当前已建立 `V:` 指向仓库；在 `V:/app` 运行 Flutter，或在 VS Code 打开 `V:/` 后选择新增的 **VaultOne 手机局域网联调（Debug）** 启动配置，再选择手机设备。

Windows 上 NDK 链接器还会遇到 Cargo 还原后的中文 `.rlib` 路径，因此 Android Rust 中间文件改放到 Gradle 用户缓存的 `cargokit/<工程隔离标识>/build` 下；该缓存必须是 ASCII 路径。若 Windows 用户目录也含中文，应显式把 `GRADLE_USER_HOME` 放到无中文目录。JNI 输出仍留在项目构建目录，不改源代码或依赖位置。

随本轮补齐了 Cargokit 的失败传播和打包门禁：Windows 包装脚本保留真实退出码；缺失 `.so` 立即失败；JNI 合并任务显式等待 Cargo，不能把只有 `.a` 的构建当作可用 APK。

安装/运行需要 USB 调试或已配对的无线 ADB；手机连接后在 `V:/app` 执行：

```bash
flutter run --debug --dart-define=VAULTONE_SERVER=http://192.168.0.4:9777 --dart-define=VAULTONE_ALLOW_LAN_HTTP=true
```

局域网白名单仅在 `android/app/src/debug/` 中，当前精确允许 192.168.0.4、127.0.0.1、localhost 和模拟器的 10.0.2.2。主 manifest 仍禁止明文；Release/Profile 不包含此 Debug 资源。

客户端还有两层门禁：Dart 只在 Debug + 显式开关时允许数值私网 IPv4；Rust 只在 debug 构建登记当前选定的完整 HTTP 端点（IP 和端口都必须匹配），不允许任意私网地址或重定向。开发 HTTP 请求不经过环境变量代理，生产 HTTPS 代理策略不变。只改 Dart define 而不重新构建原生桥不能使用新能力。

### Android USB 替代方式

不想走 Wi-Fi 时可使用 ADB 反向端口（多个设备时需指定 `-s`）：

```bash
adb reverse tcp:9777 tcp:9777
```

随后用回环地址启动，无需 LAN 开关：

```bash
flutter run --debug --dart-define=VAULTONE_SERVER=http://127.0.0.1:9777
```

Android 模拟器访问宿主机也可使用 `http://10.0.2.2:9777`。这些地址仅适合对应的开发连接方式。

## 3. iOS 真机

**必须在 Mac + Xcode 上编译、签名和运行 iPhone 应用；Windows 不能完成这一步。** Java 服务仍可运行在这台 Windows 电脑上，Mac/iPhone 与 Windows 同网即可。

在 Mac 上项目的 `app/` 中，选好已签名的 iPhone 设备后使用同样的 Debug 启动参数：

```bash
flutter run --debug --dart-define=VAULTONE_SERVER=http://192.168.0.4:9777 --dart-define=VAULTONE_ALLOW_LAN_HTTP=true
```

Xcode 的 Runner **Debug** 配置改用 `Info-Debug.plist`，包含本地网络用途说明和 `NSAllowsLocalNetworking`；没有全局 `NSAllowsArbitraryLoads`。Release/Profile 仍用原 `Info.plist`。首次连接时允许本地网络权限；此前拒绝的，在 iOS 设置中为 VaultOne 打开本地网络访问。直接访问 IP 不需要 Bonjour 服务声明。

核心 HTTP 使用 Rust reqwest 原生套接字，不把 ATS/XML 配置误当成它的唯一安全边界；真正的服务器地址限制仍由 Dart/Rust 实施。iOS 权限提示、系统版本差异与实际连接必须真机验收，Windows 下的 plist 检查不等于真机通过。

## 4. 排查顺序

1. 在**手机浏览器**打开 `http://192.168.0.4:9777/healthz`，应看到 `status: ok`。电脑自己能访问只证明本机网卡路径可达，不证明 Wi-Fi/防火墙允许手机入站。
2. 手机打不开时检查同一 Wi-Fi、访客网络/AP 隔离、VPN/代理、Windows 防火墙。当前 WLAN 被 Windows 标记为 **Public**；只对可信网络配置 Java 进程/TCP 9777/本地子网来源的入站允许，不关闭整个防火墙、不开放 PG/Redis、不做路由器公网映射。本轮未擅自修改防火墙或网络类别。
3. 手机浏览器能打开、App 失败时，确认实际启动使用上述两个 define，模式是 **Debug**，且已重新编译原生桥。iOS 检查本地网络授权；Android 更换 IP 后更新 Debug XML。
4. 既有保险库绑定了不同地址时，会要求重新验证同一账户再换绑，不会静默把 Token 发往新地址。尚未完成注册的草稿固定原端点；不要为连通测试清除有价值的本机数据，可先导出备份或用原回环地址配合 ADB reverse 完成注册。

## 5. 验收口径

Java 启动/来源门禁单测、真实私网网卡访问 Jetty（健康接口 200、未认证账户接口 401）、Rust 精确端点/发布禁用/拒绝重定向、Flutter 配置与原有业务回归均单独记录在 docs/11。Android 调试包构建与安装到手机、iOS plist 校验与 Xcode 真机运行分别报告，不能混为“跨端全通过”。
