# 01 · 模块拆分与依赖选型

> 本文回答两个问题：**每个模块用了什么现成的轮子、为什么**；以及**哪些代码是自研的、为什么不能用现成的**。
> 版本号均取自仓库中的 `Cargo.lock` / `app/pubspec.lock`（锁定版本，构建可复现）。
> 文中「计划书」指已归档的 [VaultOne-MVP开发计划书](archive/VaultOne-MVP开发计划书.md)，仅作历史对照，不采用其技术选型。

## 1. 总体架构

下图为 2026-10-01 后的开发基准：Java 承接云账户与在线业务；不代表生产已从旧 Rust 服务切流。客户端不再提供纯本地建号/可选关闭同步，SQLite 的本地优先职责是保险库条目，而非云账户权限真相源。

移动真机联调使用显式 dev LAN API 监听与真实对端私网过滤，不放开数据服务。客户端由 Dart Debug 构建参数经生成式 FRB 登记唯一私网 HTTP 端点，Rust 发布构建拒绝该例外，认证 HTTP 客户端不跟随重定向。Android Debug 精确域名白名单、iOS Debug 专属 plist 和本地网络说明与发布配置分离，无新增依赖。Windows Android 构建仍复用既有 Cargokit：修正包装脚本退出码、缺动态库门禁与 JNI 合并依赖，Rust 中间文件使用无中文 Gradle 用户缓存，避免 NDK 链接器打不开规范化后的中文路径。配置/使用方式见 [14](14-移动端局域网调试.md)。

```
┌──────────────────────── 客户端（保险库明文只在此存在） ────────────────────────┐
│ Flutter UI（Windows / macOS / Android / iOS 同一套 Dart 代码）                   │
│   app/lib/src/{ui,state,core}                                                    │
│        │  flutter_rust_bridge 2（自动生成绑定，app/lib/src/rust/**）              │
│ vaultone_bridge（app/rust）── Dart 可见 API、日志、剪贴板                        │
│        │                                                                         │
│ vault-core ── 保险库 / 本地 SQLite / 同步客户端 / 三方合并 / URL 匹配 / TOTP / 审计│
│ vault-crypto ── AES-256-GCM 密封盒 / Argon2id 双因子派生 / SRP-6a / 受保护内存   │
│ vault-proto ── 线协议；保险库密文/元数据与主动客服反馈分开定义                    │
│ 浏览器扩展（extension/）⇄ vault-nmhost（Native Messaging 转发）⇄ 本地套接字 ⇄ 桌面端│
└──────────────────────────────────┬──────────────────────────────────────────────┘
                                   │ HTTPS（rustls）；主动反馈另行明确同意
┌──────────────────────────────────▼──────────────────────────────────────────────┐
│ server/（Java MVC / Jetty）：身份 · 设备 · 同步 · 恢复 · 审计 · 邮件 · 文本反馈    │
│ PostgreSQL / JPA / Flyway：持久真相源；Redis / Redisson：会话摘要与有界协调       │
└─────────────────────────────────────────────────────────────────────────────────┘
```

与计划书 §3.3 的差异（均为有意取舍，已在 AGENTS.md 记录）：

| 计划书 | 实际 | 理由 |
|---|---|---|
| Tauri 桌面 + Swift/Kotlin 原生移动端 | **Flutter 一套 UI 覆盖 4 端** + Rust 内核 | 9 人团队 → 本仓库以最小人力覆盖全平台；密码学仍全部在 Rust 内核，UI 层零密钥逻辑 |
| Go 服务端 | **Java 21 / Spring Boot 4 服务端作为开发基准** | 保持既有密码协议，通过 Rust 客户端交叉验收；旧 Rust 服务端保留但不再扩展，未自动切流 |
| XChaCha20-Poly1305 / AES-256-KW | **统一 AES-256-GCM 密封盒** | 满足本次交付的加密规范（全部敏感数据统一 AES-256-GCM、随机 IV、随机盐） |
| SQLCipher | SQLite + **应用层逐字段 AES-256-GCM** | 本地库中除非敏感元数据外全部是密封盒；SQLCipher 需 OpenSSL 交叉编译 5 个平台，收益有限（见 docs/03 §6） |
| Redis 会话/限流 | Java 采用 Redis 会话摘要索引与有界限流 | PG 保留权威账户/设备代次，Redis 不缓存保险库内容或反馈正文；服务故障安全拒绝 |

## 2. 模块清单与依赖选型

### 2.1 `crates/vault-crypto` — 密码学编排（不实现任何算法）

| 用途 | 依赖 | 锁定版本 | 选型理由 |
|---|---|---|---|
| 对称加密（唯一模式） | `aes-gcm` | 0.10.3 | RustCrypto 官方实现，NCC Group 审计（2020），常量时间、支持 AES-NI/ARMv8 硬件加速 |
| 子密钥派生 | `hkdf` + `sha2` | 0.12.4 / 0.10.9 | RFC 5869 标准实现 |

| 内存清零 | `zeroize` | 1.9.0 | 编译器屏障保证不被优化掉 |

### 2.3 `crates/vault-core` — 客户端内核

`cloud_account.rs` 编排在线身份操作，复用既有 reqwest/SRP/密封盒及 Store 事务，不新增密码算法或依赖。`cloud_account_operation` 保存固定候选凭据与基线，恢复套件用 Vault Key 加密保存；HTTP 在 SQLite 事务外，远端确认后以完整基线/候选比较原子提交本机账户和会话。改密响应丢失可对账，新旧密码按候选重试；恢复支持同账户原地更新，保留条目。云退出清除本机会话令牌但保留绑定与条目，不把账户变回纯本地。底层本地建号/恢复原语仍供密码学与兼容测试使用，不再接入产品注册/恢复门面。见 [13](13-云账户与本地优先保险库.md)。

### 2.9 `server/` — Java 服务端迁移实现（S2/S3 已实现，真实集成验收通过）

独立 Maven 工程，不加入 Cargo 工作区，不替换正在使用的 Rust 服务端。MVC/Jetty、部署守卫、多环境 YAML、协议/密码学适配以及身份/账户/设备/恢复/审计/同步业务均已实现并提交（`ec83b6a`），Redis 用于会话摘要索引与非敏感元数据。单元/格式/架构测试 105 项通过；2026-10-01 复核修复了 external/容器 IT 启动被 `DeploymentGuard` 拒绝的测试夹具缺陷后，external `verify` 105 单测 + 31 真实 PG/Redis/Jetty IT（含 Rust 客户端互通）全绿，容器路径由 CI 覆盖。详见 [docs/11 §7](11-计划执行与验收记录.md)。客户端线协议不变，生产尚未切流。

| 用途 | 依赖 / 版本 | 理由与边界 |
|---|---|---|
| Java / 构建 | Java 21、Initializr Maven Wrapper | 使用已有 IDEA SDK或进程级JAVA_HOME，不改变系统默认Java；CI 单独执行 verify |
| MVC / Web | Spring Boot 4.1.1、Jetty 12.1.12 | 复用官方 starter；真实 Jetty 请求虚拟线程测试，不以配置字符串代替运行验证 |
| ORM / 审计 | Hibernate / Envers 7.4.5.Final | 同一Boot BOM、validate、OSIV=false；业务实体采用非敏感审计白名单，修订元数据与RLS仍需真实PG验收 |
| 数据库迁移 | PostgreSQL 驱动、Flyway（Boot BOM） | 独立Java迁移链，禁止自动baseline；运行与迁移角色分离，不自动接管旧SQLx库 |
| Redis | Redisson 核心 4.7.0 | 单客户端与有界资源；会话仅存Token摘要索引/元数据，缓存不含保险库密文、密钥或恢复材料；撤销仍须有持久权限依据 |
| Java 密码适配 | Bouncy Castle 1.86、JDK JCA / BigInteger | BC提供HKDF，JCA提供AES-GCM/HMAC/SHA256，按既有Rust字节契约组合；不使用不兼容的默认SRP证明格式，不重写密码原语 |
| Jakarta EL | Expressly 6.0.0 | 替代Tomcat EL，严格排除Tomcat组件；真实校验/EL插值测试 |
| 运行日志 | SLF4J / Logback（Boot BOM） | 复用成熟日志门面与轮转实现；运行诊断、用户安全审计、Envers修订分离，禁止秘密或请求体进入日志 |
| 测试与格式 | ArchUnit 1.5.1、Testcontainers 2.0.5、Spotless 3.10.3 / google-java-format 1.36.1 | 格式/分层与真实基础设施门禁；CI可用容器、本机显式使用已有PG/Redis，同一套断言，不以H2/mock/跳过替代 |

服务入口为 `app.vaultone.server`。业务模块包括 `identity`、`account`、`sync`、`audit`、`feedback`，横切模块为 `config`、`security`、`web`、`common`、`crypto`、`proto`、`validate`。Controller 只处理 HTTP 边界，事务与状态转换由 Service 完成；Entity 不作为响应。配置按 `application.yaml` / `application-dev.yaml` / `application-prod.yaml` 分层并内联，保留显式环境与启动安全门禁。

E11 的用户通道为 `feedback/controller → service → repository`，复用 Approved + 事务内 AccountGuard、账户锁与 FORCE RLS；正文/联系方式/最近客服回复只存 PG，不进入 Redis 或 Envers。`V5` 增加反馈表、保留清理窄函数和操作审计的 operator/target 元数据。限长、同意、账户额度、幂等与分页契约见 [12](12-文本反馈契约与运维.md)。客服入口 `feedback-ops` 启动独立的非 Web Spring 上下文，只导入 JPA/反馈读取处理/审计仓储；不加载 Web、Redis、邮件、定时器或 Flyway，不新增管理 Token。授权来自服务器操作系统/受限运行配置访问权，每次指定账户，并校验运行身份不是 owner/超级用户/BYPASSRLS。

客户端新增 `vault-proto::feedback`、`vault-core::feedback`、`app/rust/src/api/feedback.rs` 及生成绑定，复用既有 reqwest/Bearer（不把 token 导出到 Dart）。`VaultApi._network` 和 AppState 会话门禁保护提交/读取，设置页提供 `FeedbackPage`；反馈状态不触发保险库同步，没有离线补发或磁盘明文草稿。此批未新增第三方依赖。

密码学黄金向量通过不等于客户端互通；RLS脚本存在不等于受限角色可用；Redis锁不能替代PG约束和同步提交顺序。精确进度、真实命令和剩余阻塞见 [docs/11](11-计划执行与验收记录.md)，版本证据与启动方式见 [server/README](../server/README.md)。

## 3. 自研代码（仅限核心创新）及其不可替代性

除下列 4 项外，仓库中其余自研代码都是「把成熟库按固定规则组合」的胶水与业务流程。

### 3.1 零知识字段级三方合并（`crates/vault-core/src/merge.rs`）

- **问题**：E2EE 同步中服务端看不到明文，无法像普通同步服务那样在服务端合并；常见 E2EE 同步方案对并发编辑采用「整条目后写覆盖」，两台设备离线分别修改同一条目的不同字段时，一方的修改被静默丢弃（违反计划书 F-06/A-05）。
- **做法**：客户端保留最后确认的密文基线及删除状态。无冲突的不同字段继续自动合并；真正同字段或删除/编辑冲突由 `conflict.rs` 加密保存 base/local/remote 完整候选并暂停该条目推送。用户整条或逐字段裁决后，本机事务核对完整条目与冲突快照，再排入同步；服务端确认前不把本地选择当成已同步。
- **不可替代性**：冲突判定、删除语义和人工裁决是保险库业务规则，明文处理始终在客户端；加密、SQLite 事务与协议序列化分别复用现有 sealed/rusqlite/serde，不引入新密码学算法或云端明文合并。服务端用同账户事务串行化保证版本检查与游标提交顺序，JSON 协议保持不变。
- **验证**：`conflict_tests.rs` 覆盖持久化/重启、过期与重复裁决、损坏数据、墓碑、锁定与导出边界；`store.rs` 覆盖旧库迁移和事务回滚；`sync_concurrency.rs` 覆盖真实 HTTP 并发推送，PG 专项仍需实际环境。Flutter 通过生成式 FRB 接通 `conflicts_page.dart`，组件与桌面集成测试分别覆盖裁决交互和真实桥接入口。

### 3.2 防钓鱼自动填充匹配策略（`crates/vault-core/src/urlmatch.rs`）

- 公共后缀判定完全复用 `psl`；自研的是**匹配策略**：协议降级拒绝（https 条目不在 http 页面匹配）、IP/单标签主机禁止放宽、未收录公共后缀不放宽、punycode 比较抵御同形异义字、Exact > Host > Domain 打分排序。
- **不可替代性**：现有库只回答「这个域名的注册域是什么」，不回答「这个页面能否安全地填充这条凭据」；后者是密码管理器的核心安全决策（计划书 S-06 / B-06），必须由产品自己定义并测试。
- **验证**：7 个单元测试，覆盖 github.io 私有后缀、SSL strip、西里尔字母 а 仿冒、IP 端口不同等钓鱼场景。

### 3.3 AES-256-GCM「密封盒」格式与密钥层级编排（`crates/vault-crypto/src/sealed.rs`、`kdf.rs`）

- 原语全部来自 RustCrypto；自研的是**格式与组合规则**：每次加密随机 32 字节盐 + 12 字节 IV，经 HKDF 派生一次性消息密钥，头部（版本、套件、盐、IV）纳入 GCM 认证；主密码 × Secret Key 双因子派生（2SKD）。
- **不可替代性**：没有现成库同时满足「统一 AES-256-GCM、每次随机 IV、每次随机盐、盐与 IV 随密文存储并受认证、可版本演进」这组约束；`age`、`libsodium sealed box` 分别绑定 X25519/ChaCha20，不符合规范。
- **优势**：每条消息使用由随机盐派生的一次性子密钥，彻底消除同一长期密钥下 96-bit 随机 IV 的生日界（2^32 条消息）风险。
- **验证**：逐字节篡改检测、AAD 边界、已知答案复算（第三方可按 `docs/03` 独立实现解密）等 8 个测试。

### 3.4 浏览器扩展配对与请求认证（`crates/vault-core/src/browser.rs`）

- 原语是 HMAC-SHA256 与 SHA-256；自研的是**协议**：扩展生成 256-bit 配对密钥，桌面端显示由其派生的 8 位配对码供用户核对后批准；此后每个请求带 `HMAC(密钥, 域分隔‖clientId‖nonce‖ts‖body)`，±120 s 时间窗 + nonce 去重防重放；配对密钥以 Vault Key 密封存储，锁定时一律返回 `locked`。
- **不可替代性**：Native Messaging 只保证"是某个浏览器扩展在调用"，不保证是**本用户批准过的**扩展，也挡不住同机其他进程直连本地套接字；现成密码管理器的做法都绑定在各自产品里，没有可复用的库。释放凭据前还要经过 §3.2 的 URL 匹配，扩展即使被攻破也只能拿到当前页面匹配的那一条。
- **验证**：`browser.rs` 7 个单元测试（重放、错误密钥、过期时间戳、钓鱼域名拒绝、保存 / 更新、与 JS 实现的固定交叉向量）；`app/rust/src/api/browser.rs` 在真实本地套接字上、并经真实宿主进程转发的端到端测试。
