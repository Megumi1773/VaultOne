# 12 · E11 文本反馈契约与运维边界

> 2026-10-01 开发契约；实现和实测结果以 [11 执行记录](11-计划执行与验收记录.md) 为准。基准后端为 Java `server/`，不在 Rust 服务端重复建设。

## 1. 本批范围

- 已连接云账户的用户主动提交文本反馈，查看分页历史、详情、处理状态及客服最近回复。
- 类型为 `bug`（问题）、`suggestion`（建议）、`other`（其他）；状态为 `open`、`in_progress`、`resolved`。
- 客服通过服务器本机显式启用的命令行入口读取指定账户的工单和更新处理结果；不新增公网管理员 HTTP、不把普通账户提升为客服、不配置默认管理 Token。
- 多轮线程、图片附件、推送通知与客服管理网页不在本批。单个 `reply` 是最近处理说明，不宣称完整对话历史。

## 2. 隐私与数据生命周期

反馈不是保险库同步内容。提交前单独确认：文本和可选联系方式可被客服读取；不要填写密码、Secret Key、恢复码或保险库内容。客户端不得自动附带条目、设备诊断、邮箱、日志、剪贴板、PDF 或密钥。

反馈正文、联系方式和客服回复只保存在 PostgreSQL，不进入 Redis、运行日志、操作审计或 Envers。客户端仅在当前已解锁页面内存保存草稿/列表/详情，关闭或锁定即销毁，不做明文磁盘缓存。受保护请求经过现有隐私同意、解锁、云会话及设备批准门禁；云端不可用不妨碍合法本地保险库使用。

反馈自创建起按有界配置保留（默认 180 天），到期不可读取/处理，定时分批物理清理；注销时通过账户外键级联删除。处理回复不延长保留期。操作审计只存动作/对象 ID/等级/结果/请求关联，沿用既有审计保留策略，不保留反馈内容。生产 PG 备份的离线留存仍须由部署方按保留政策清理。

## 3. 用户 HTTP 契约

沿用 `/v1`、snake_case、Unix 秒、有界 JSON 和既有 `{code,message}` 错误；不改变任何既有成功 DTO。所有反馈接口要求已批准设备的 Bearer 会话，账户从认证取得，绝不采用请求体的账户归属。

### 提交 `POST /v1/feedback`

```json
{"id":"123e4567-e89b-42d3-a456-426614174000","category":"bug","content":"重试同步后提示一直未消失","contact":null,"consent":true}
```

- `id`：客户端预先生成的规范小写 UUID，作为账户范围内幂等键。同一提交重试必须保持 ID 和内容不变；不同提交生成新 ID。
- `content`：去除首尾空白后非空，最多 4000 UTF-16 代码单元；`contact` 可为 null/空（规范化为 null），非空最多 200。允许普通换行，不支持 HTML/Markdown 动作或链接执行。
- `consent` 必须显式为 true。类型、长度、ID、未知字段遵循严格输入校验；语义参数错误为 400，JSON 字段结构不符（包含未知字段）沿用 422 `unprocessable_entity`，不修改既有异常映射。
- 首次创建返回 201 和详情；同账户同 ID 同规范化内容重试返回 200 和当前详情，不重复创建或审计；同 ID 不同内容返回 409 `conflict`。幂等有效期为反馈保留期，不承诺到期清理后永久去重。
- 按账户限制提交频率和有效记录数量，重放不消耗新的创建额度。已到期但尚待物理清理的 ID 重放返回 409，不复活到期内容；清理后不保留正文/永久幂等记录。响应丢失不能被客户端当作“服务端一定未保存”。

### 历史 `GET /v1/feedback?before=<cursor>&limit=20`

返回 `{"items":[...],"next_before":null}`。默认 20，最大 50；`before` 为空表示最新一页，否则为正整数游标，结果按不可变创建顺序倒序。列表仅包含 `id/category/status/created_at/updated_at/version`，不带正文、联系方式或回复。处理状态变化不重排历史。

### 详情 `GET /v1/feedback/{id}`

返回摘要字段以及 `content/contact/reply`。不存在、其他账户、过期记录统一 404，不暴露其存在。回复为纯文本，UI 不解析服务端可执行动作。

## 4. 处理入口

仅有服务器配置和操作系统执行权限的授权人员可以显式运行 `feedback-ops`。输入/输出包含用户主动提交的内容，必须在受控终端读取，不记录 shell 命令正文、不贴入日志或公共工单。

- 每次请求显式传入规范账户 UUID，事务使用现有 RLS 账户上下文；无全账户导出、无任意 SQL、无任意表访问。
- 支持指定账户分页列表、详情和更新处理结果。更新带 `id/expected_version/status/reply`；回复最多 4000 UTF-16 单元，`resolved` 必须提供非空回复。
- 版本不匹配返回冲突，不覆盖其他处理人的新结果；完全相同的一次重试可返回当前结果。失败不留下成功审计，成功处理与最小操作审计同事务提交。
- 运维入口不监听 HTTP，不自动接管旧库。生产运行与角色授权单独验收。

## 5. 客户端交互

沿用已有 `ZoColors` / Material / 中文字体体系。浅色使用现有纸白 `#F6F6F3`、白色表面 `#FFFFFF`、正文 `#0B0B0C`、次要文本 `#5B5B63`、强调蓝 `#2457E6`；暗色直接使用主题对应令牌。标题 20、正文 13.5–15，左对齐，表单最大宽度约 720；不添加主题、动效库或 shadcn。

```text
意见反馈                                      刷新
说明：客服可读取，勿包含恢复材料
[写反馈] [历史记录]
类型 / 文本 / 可选联系方式
[ ] 我理解上述信息会发送给客服
[提交反馈]        失败时保留本次提交用于原样重试
-----------------------------------------------
历史：类型 + 状态 + 时间（分页）
详情：提交正文 / 当前状态 / 客服回复
```

隐私说明作为唯一强调区，其余复用安静的表单/列表。提交前可取消并丢弃草稿；请求开始后关闭页面只停止展示，不承诺撤销已发送请求。网络结果未知时保留原请求 ID 用于重试，并允许查看历史确认；不自动用新 ID 重发。锁定、会话变化或晚到回调不能重新展示内容。

## 6. 验收

- 真实 PG/Redis/Jetty：创建/重放/冲突、严格输入、分页、账户隔离和空上下文 RLS、未批准/撤销会话、处理 CAS、内容日志脱敏、保留清理、注销级联。
- Rust 生产客户端调用 Java：提交/列表/详情/重试；FRB 从 Rust 源码重新生成，不手改绑定。
- Flutter：告知及显式同意、类型/长度、成功/失败/空态、分页/详情/处理状态、取消/重试、关闭和锁定后的晚到结果不回填。
- 原有 Java、Rust、Flutter 门禁继续执行；未具备的真实设备、生产操作与容器路径单独记录，不以测试替代。
