### 1.1 不照搬旧实现

仅对照业务能力，不迁回 SECP256K1 / AES-CBC、旧 Base64 私钥规范、负数本地 ID、东八区无时区时间或旧 HTTP 501/423 约定。继续使用现有 Argon2id / AES-256-GCM / SRP-6a、Secret Key 解析与协议错误码体系。

- 保留当前 Flutter + Rust、SQLite 本地真相源、零知识服务端、生成式 FRB 桥。
- 不强制恢复“首页 / 保险库 / 安全 / 我的”四 Tab，也不要求按旧 URL 拆成相同数量的页面；对话框、设置区块或侧栏可以承载等价能力。
- 基线标题写 66 个路由，但编号列到 68，且签到记录存在合并计数；**以功能和用户流程验收，不采用路由总数作进度分母**。
- 老 passmgr 数据格式兼容与老密码学账户迁移是两件事：支持迁移文件不意味着可直接解密旧 `.wljbak`。旧格式兼容须有版本识别和真实样本，未验证前不得宣称互通。
- P2 的账户限制只限制云服务权限，不应为了照搬旧“账户锁定”而阻断用户访问已经合法解锁的本地数据。

## 2. 已确认的关键差距与证据

### 2.1 E1：加密备份恢复去重可能漏条目

[普通导入去重](../crates/vault-core/src/vault.rs:381) 只比较标题、用户名、密码和首个 URL；[备份恢复](../crates/vault-core/src/vault.rs:421) 复用该规则。两条同名但正文不同的笔记、同名但卡号不同的卡片可能被当作重复，导致其中一条不被恢复。

其他明确边界：

- `.wljbak` 由当前 Vault Key 密封并绑定账户，不是仅持有文件即可恢复，也不是独立备份密码模式。
- 导出来自正常条目列表，不含回收站；导入重建 ID 与创建/更新时间，不是数据库快照回滚。
- CSV 是迁移格式，当前仅有限列，不能无损承载所有条目类型、自定义字段、多 URL、历史与 TOTP 配置。不能用 CSV 的限制推导加密载荷本身不完整，也不能宣传 CSV 为完整备份。
- 损坏条目跳过、导出数量及不支持字段需要明确汇总，不能只报告文件已保存。

### 2.2 E4：冲突解决需要补全数据链路

[自动合并](../crates/vault-core/src/merge.rs) 已实现，败方密码会保留到历史；[同步落库](../crates/vault-core/src/sync.rs:580) 直接写合并结果，冲突主要计数和记录日志；[桥接返回](../app/rust/src/api/sync.rs:9) 只有冲突数量。人工裁决必须补可持久化冲突记录、字段与双方版本、解决接口，不能只做一个列表页。

### 2.3 已完成能力不要重复开发

- [导出 / 导入 UI](../app/lib/src/ui/screens/settings_page.dart:719) 已接通，底层见 [export.rs](../crates/vault-core/src/export.rs)。
- [恢复套件 PDF](../app/lib/src/state/recovery_kit.dart:21) 已实现 A4 输出、移动端分享及桌面保存；不要重新造 PDF 生成器。
- [服务端路由](../crates/vault-server/src/lib.rs:143) 已覆盖认证、设备、恢复、账户、审计、同步，不含通知、积分、反馈或版本发布接口。
- 浏览器扩展、Android AutofillService 已有代码，下一步首先是实际运行验收；iOS Credential Provider 仍需新增工程。

## 3. 开发包与执行顺序

保留 E1–E12 旧编号便于追踪；新增 G 编号表示此前计划遗漏的业务差距，Q 表示质量验收。除 E9 外，未实现功能均进入本计划；带“后置”的条目不是已取消。

### 阶段 A：数据安全收口与质量基线（优先）

#### Q1 · 恢复可重复的质量门禁

- 修复当前 `routes_auth.rs` 的格式差异。
- 在不干扰已有服务的环境运行全量 Rust 测试；必要时使用独立构建输出目录，而不是直接杀掉正在使用的服务。
- 重跑 clippy、Dart 静态分析、Flutter 单测和桌面集成测试。
- 为 `DeepSeek41` 开发分支建立可验证的 CI 入口：通过 PR 触发或调整明确的分支触发规则；不把“存在 CI 文件”当作当前分支已验证。
- 针对近期时间列变更补 SQLite / PostgreSQL **旧库升级**测试；只验证空库迁移成功不够。
- 将“已有保险库但隐私同意标记缺失”、锁定后已打开页面和异步返回列为优先安全回归；若证实存在同意前联网或锁定后敏感页面仍可访问，先修复再放行，不等到国际化阶段。
- 验收：记录 commit、命令、环境、通过数、跳过项与失败原因；数据库升级后登录、过期判断、同步与审计时间正确。

#### E1-R · 备份与导入正确性

- 明确当前备份产品语义：条目级恢复还是快照恢复。第一阶段以条目级恢复为默认，不承诺回滚数据库；恢复 ID/时间、回收站是否包含必须写入格式说明和 UI。
- 为备份恢复设计不会误吞不同内容条目的去重/身份规则，不能继续直接依赖四字段指纹；普通导入的同类误去重一起覆盖。
- 保留格式版本、账户绑定、完整性校验；明确灾难恢复所需材料，并测试在新安装环境恢复账户后导入备份。
- 明文 CSV 导出需要风险确认，报告有损字段；不支持的内容不得悄悄宣称成功迁移。
- 导出报告条目数、跳过/失败原因、文件大小与实际保存位置；写入失败不显示成功，不把敏感内容写入日志。
- 验收：同名不同卡/笔记、跨类型同名、多 URL、自定义字段、完整 TOTP 配置、重复恢复、错误账户/密钥、截断/篡改、大文件、磁盘写入失败；失败不能破坏原保险库。

#### E3 · 浏览器、Android 与跨端同步实测（并行）

- Chrome / Edge：宿主发现、首次配对、锁定/解锁、填充、保存新条目、更新密码、TOTP、取消操作、不匹配域名拒绝填充。
- Android 真机：启用服务、跨应用填充、认证界面返回、保存/取消、进程重启、多 Flutter 引擎、剪贴板与隐私行为。
- 双端：离线修改后重连、删除与恢复、令牌失效、设备撤销、同字段冲突、主密码更改、备份恢复后同步。
- 记录设备/系统/浏览器版本、应用 commit、复现步骤与结果。协议测试成功不能代替上述验收。

**阶段出口：** 去重导致恢复漏条目的问题已修复且有回归；目标平台主要用户流程有实际证据；质量门禁可复现。未通过的平台不写入发布支持承诺。

### 阶段 B：冲突与恢复能力

#### E4 · 人工冲突处理

- 在本地加密保存待裁决冲突：条目、基线、双方版本/字段、版本关系、产生时间与解决状态；避免以明文持久化冲突内容。
- 定义自动合并与人工裁决的边界，保留目前能无损自动合并的行为。
- 新增列表/详情/解决接口，重新生成 FRB；提供保留本地、保留远端及可解释的字段合并交互。
- 裁决时验证条目是否已有更新，避免用户打开旧冲突页后覆盖新内容；解决和同步幂等。
- 验收：同字段冲突、不同字段自动合并、编辑与删除冲突、解决前再次同步、解决中断/重启、两端并发裁决、败方数据可追溯。

#### E7 · 备份卡、二次确认与备份状态

- 复用现有 PDF，增加备份卡图片、相册/分享适配与安全提示。
- 通过当前 Secret Key 统一解析入口进行字节级二次确认，不引入旧 44 字符或 SECP 标量规则。
- 分清“点击复制 / 文件生成 / 用户确认备份”的状态；复制任意一段不算完成完整恢复材料备份。
- 记录最近备份方式、时间与提醒状态。需要跨设备历史时只上传最小动作元数据，绝不上传密钥、二维码或 PDF 内容。
- 后续密钥变更须使旧确认状态失效，并引导重新备份。
- 验收：取消、分享失败、保存失败、确认错误、重启、密钥变更、跨设备元数据失败提示；PDF 和图片均可实际读回。

### 阶段 C：保险库功能完整性

#### E6 · 分组 / 分类 / 标签与组织检索

- 区分条目类型、用户分类、树形分组、多标签；不把现有四种类型改名后算作分类体系完成。
- 明确删除分组/标签、移动子树、稳定排序、后代条目计数与无分类兜底规则。
- 元数据随保险库加密同步；新增字段必须验证旧客户端往返不会静默丢失新数据，必要时进行显式版本兼容门控。
- 提供列表、子列表、筛选及编辑入口；和导入文件夹映射、模板关联联动。
- 验收：离线编辑、重复名称、深层树、环路拒绝、跨端并发移动/删除、旧备份恢复、旧客户端兼容。

#### E5 · 条目模板

- 以当前字段模型实现本地预置模板，复用成熟 UI 组件；不从旧项目复制架构。
- 从模板建立可编辑条目，支持字段验证、敏感标记、类型与可选分类。
- 先完成字段模型约定，再与 E6 并行实现；分类关联依赖 E6 的稳定契约。
- 验收：模板创建后可保存、同步、导出和恢复；修改条目不反向污染模板。

#### G1 · 动态字段、草稿、条目展示与首页组织

- 对照字段能力补日期、图片/附件、图标及应用/域名绑定编辑；数据结构存在不代表编辑器已可用。
- 图片/附件先明确加密存储、跨端可达、大小限制、缓存清理和备份格式，再实现选择、裁剪/压缩、预览、删除。不得用明文远程 URL 冒充端到端加密附件。
- 草稿加密保存、按账户与条目隔离；定义锁定后不可读、重启恢复、保存后清理、过期和放弃行为，不存入明文偏好设置。
- 补回收站单项彻底删除与批量清空，设计跨端删除语义后再实施；补分组排序、首页板块排序与需关注提示。**设置页已有待同步数量和最近同步时间，作为回归项，不重复开发。**
- 首页自定义复用现有主框架，补顺序、可见性与快捷入口；远端定义板块后置，优先本地可用，不能让首页依赖联网。
- 验收：锁定/崩溃/切换条目不泄露草稿；字段全链路无损；回收站批量操作可取消并明确不可逆边界。

#### G2 · 导入 / 导出体验补齐

- 增补 1Password `.1pux`；不能将已支持的 CSV/1PIF 视为 `.1pux`。KeePass 常见 CSV 列可被当前通用别名覆盖，先用真实不同版本/导出变体建立兼容矩阵，失败的变体再补适配，不直接判定全部不支持。
- 字段映射、最多 20 条预览、解析警告、文件夹/收藏映射、目标分类。
- 支持跳过 / 覆盖 / 两者保留，覆盖有清晰匹配规则与风险提示，不误改不同条目。
- 展示处理进度与可理解的失败原因；本地导入/导出历史仅留最小元数据，禁止保留密码或解析后的明文预览。
- 适配打开所在目录、移动分享与真实文件保存结果；解析器限制大小、条目数与解压资源消耗。
- 验收：真实各格式样本、BOM/多行/编码异常、格式伪装、超大压缩包、重复策略、取消与部分失败、无服务端明文传输。

### 阶段 D：安全、账户与跨平台体验

#### G3 · 安全中心与可配置隐私

- 平台保护能力按操作系统能力说明；应用切换遮罩不等于所有平台都能阻止截图。
- 验收：后台/休眠/恢复、不同剪贴板内容、锁定与异步任务竞态、权限拒绝、环境探测不可用、忽略项到期。

#### G4 · 账户安全与身份生命周期

- 补云账户锁定/封禁展示与服务端强制门禁，区分自动限制和管理员限制；保留合法本地离线访问，云端限制不得只靠前端隐藏入口。
- 统一过期、撤销、恢复、设备批准等错误流转，不要求复刻旧会话枚举或错误码。
- **Secret Key 查看已实际验证主密码，保留并补回归。** 单独设计密钥轮换与格式升级；当前未见独立轮换 UI，实施前核对恢复流程已有能力，不能将“改主密码”当作 Secret Key 轮换。
- 密钥轮换前明确已有设备、旧恢复套件、备份、同步封装与失败回滚的兼容性；不得为追求对齐仓促替换密码学方案。
- 补联系邮箱/手机验证和偏好、设备详情及资料入口。手机号是新增收集项，需服务端验证、防枚举/限流与隐私文案同步；昵称/头像与联系方式分开管理。
- 验收：过期/撤销期间离线条目不丢失；账户限制不能绕过云 API；密钥轮换中断可恢复；新旧设备状态明确；联系方式变更需要重新验证。

#### G5 · 国际化、外观、关于与合规

- 补简中 / 繁中 / 英文业务文案与语言切换，统一文案资源和格式化；**跟随系统 / 浅色 / 深色三模式已实现，复用并补回归，不重新开发主题系统**。
- 补关于页版本/构建号、版权、官网、用户协议及隐私入口；官网法律文案是否真实上线单独验收。
- 确认隐私同意前无业务网络请求，包括后台初始化与后续新增通知/更新检查。
- 路由与锁定守卫验证包括深链、通知动作、系统返回和异步完成，不以页面数量验收。
- 验收：文案覆盖、长文本/大字体、语言切换、重启保持、暗色与无障碍、协议不可用提示、首启网络抓取。

## 4. 排期依赖与实施约束

### 4.1 推荐执行节奏

### 4.2 工程约束

- 在 `DeepSeek41` 上小步提交；本文不授权提交、推送、发布或修改线上服务。
- 优先使用成熟库与现有组件。新增依赖或改变模块边界时更新 `docs/01`；密码学/密封格式变更更新 `docs/03`。

### 7.2 MVC 分层与工程边界

采用**按业务域组织、域内 MVC 分层的模块化单体**，不是微服务拆分。新增目录为 `server/`，Java 包建议 `com.vaultone.server`；认证、账户、设备、恢复、同步、审计分别拥有 `controller / dto / service / model / repository` 子包，共享横切能力置于 `config / security / crypto / common`。

- **Controller**：`@RestController` 负责路由、Bean Validation、请求/响应转换与状态码，不访问 Repository、不写事务、不执行密码学。API 的 View 是 JSON DTO，Flutter 是独立客户端，不增加 Thymeleaf/JSP 页面。
- **Service**：承载用例、权限、状态转换、幂等和短事务；一个公开事务方法只处理一个明确用例，不把流程都塞进 Controller。服务间通过明确接口调用，避免自调用绕过 `@Transactional` / AOP 代理。
- **Model / Repository**：Entity 只表达服务端可见的元数据与不透明密文；Repository 负责带账户范围的查询、CAS、必要的显式锁。禁止将 Entity、Hibernate Proxy、惰性集合直接作为 HTTP 返回值；DTO 映射在事务内完成。
- **Security / Crypto / Infrastructure**：过滤器负责解析既有 Bearer 凭据，服务层再次执行对象级授权；密码学封装成熟库与现有协议适配器；邮件、PG、Redis 各自集中配置。禁止 Controller 直接调用 Redisson 或拼 SQL。
- `@RestControllerAdvice` 统一转换到现有协议错误结构。Spring Security 的认证失败/拒绝访问处理器也必须使用同一结构；不将旧接口自动改成 Problem Details、新错误码或重定向登录页。
- 用 ArchUnit 约束依赖方向（Controller → Service → Repository）及禁止跨层访问；不要求每个 Service 都额外造一层无意义接口。`docs/01` 在 S1 随真实模块落地同步更新，避免提前把目标架构记成已实现。

### 7.3 零知识与 Rust → Java 协议兼容

**迁移替换的是服务端实现，不是密码协议。** S0 以当前 `vault-proto`、`vault-server`、`vault-crypto` 与 `vault-core` 客户端为真相源，生成路由/DTO/状态码/错误码/字节向量清单；不得只照文档中的“19 个路由”手写另一套接口。

- 保留 `/v1` 下注册、SRP 登录两阶段、退出、设备自查/验证/批准/撤销、账户读取/删除/凭据变更、恢复三阶段、审计、同步 pull/push 和 `/healthz`、`/readyz`。注册成功仍为 201；其他既有成功响应不能随意改成无体 204。保留 `{code,message}`、稳定错误码和客户端对认证/设备未批准错误的分流，不照搬 Spring 默认错误页。
- JSON 保留 snake_case、标准 Base64 文本、lowercase 枚举、nullable 字段和 64 位 Unix 秒（与 PG 内部 TEXT 时间分开）。Java `Instant` 不能直接变成新的 ISO JSON 格式；二进制字段按既有 DTO 的 Base64 约定显式映射，不依赖 Jackson 对 `byte[]` 的默认行为或在整数数组与文本之间擅自切换。通用请求 1 MiB、push 64 MiB 与各接口输入约束逐项回归。
- SRP 为 **3072 位组 / SHA-256**，identity 是 account_id、客户端 password 输入是二进制 AuthKey；对齐大小端、定长补零、`u/k/M1/M2` 计算与非法公开值拒绝，Java `BigInteger` 必须按无符号数解释。优先评估 Bouncy Castle 的 SRP 原语，但不假定其默认证明格式与 Rust 完全一致，不自研大整数密码原语。
- 邮箱继续使用既有带长度前缀/域分离的 HMAC 索引与 AES-GCM 密文；保留 server secret 派生用途、AAD、nonce/tag/密封格式和密钥版本。密封盒 version/suite、32 字节盐、12 字节 IV、16 字节 tag、HKDF 与 AAD 长度编码均需交叉向量。迁移不换 server secret，不重算成不兼容索引，不要求用户重新上传主密码或 Secret Key。
- 保险库条目、恢复包与密钥信封始终是不透明密文；Java 服务不得获取 Vault Key、AuthKey、主密码、Secret Key、条目明文或 TOTP 种子。邮件投递所需邮箱只在受控边界短暂解密，不进入日志、Redis 或审计快照。
- 保留非 JWT Bearer 令牌的线协议，Java 改由 Redis 以 token 文本摘要管理会话 TTL 与节流滑动续期；PG 的账户/设备状态及独立会话失效代次保证撤销即时生效，不按每次请求写数据库。未知邮箱继续使用确定性诱饵，新设备 OTP 600 秒/最多 5 次，未批准不下发 keys。**普通改主密码当前不撤销旧会话；恢复则轮换材料、递增 vk_gen 并撤销全部旧会话**，不得用 vk_gen 直接充当会话失效代次。`expected_vk_gen` 当前实际传入客户端已递增的新代次，Java 必须按旧客户端语义适配，不能凭字段名改成旧版本值。
- 当前 SRP 临时私值已经密封存入 PG 的 `handshakes.b_enc`，不是纯内存状态；Java 保留兼容的密封持久化并加强一次消费，见 §7.7，不把迁移做成 JWT/OAuth 替换工程。
- 协议兼容不等于复制已有竞态：握手原子消费、改凭据 CAS 影响行数、同步版本条件更新、恢复更新时再次校验旧恢复凭据必须以目标安全语义和并发测试验收；有缺陷的读后写行为不作为兼容要求保留。
- 同步 push 每批最多 500、逐项 applied/conflict，同 revision + blob 哈希的重放视为成功；pull 按 `change_log.seq` 分页（默认 500、上限 1000），保留墓碑、has_more、vk_gen。`change_log` 每条目仅留最新行，不是完整事件流；客户端负责三方合并。**JPA `@Version`、Envers REV、协议 revision 和同步 cursor 各有职责，不能互相替换**；新内部 `row_version` 如有必要应独立字段，不重置现有线协议版本。
- 条目信封 v2 的 wrappedKey/ct、256 字节填充和 revision/AAD 绑定保持不变；迁移逐字节搬运不透明 blob，不重序列化、不改 ID、不重编号 revision。用旧客户端调用 Java、Rust/Java 交叉向量和真实 PG 数据迁移证明兼容，不能只用 Java 自己注册再登录证明迁移成功。

### 7.4 Java 21 虚拟线程与 Jetty

- 启用 `spring.threads.virtual.enabled=true`，需要维持进程存活时设 `spring.main.keep-alive=true`。在**真实 Jetty 请求和 MVC 异步执行器**上断言 `Thread.currentThread().isVirtual()`；不能仅看到配置开关就声称请求已跑在虚拟线程上。
- 先检查所选 Boot 补丁的 Jetty 自动配置；仅在确认未接入时使用 `JettyServletWebServerFactory` 定制线程池的 virtual executor，并管理其关闭，禁止叠加两个 executor。Jetty acceptor / selector 等底层 I/O 工作保留有界平台线程，业务阻塞 I/O 交虚拟线程。
- 平台 worker 池“小而够用”，**不是任意设成 1 或 2**：`QueuedThreadPool.maxThreads` 必须覆盖 leased 线程与处理余量，按 acceptor/selector/reservedThreads、CPU 和负载实测。Jetty 内部任务队列遵守官方要求，不用缩小它来做业务背压；背压放在入口/用例并发预算。
- Hikari 连接数不因虚拟线程增加而调大；先沿用受控小池，按数据库实测确定初值（如每实例 8 个仅是压测起点）。所有实例池上限、迁移/运维连接之和须低于 PG 可用连接预算；设置有限连接等待、事务/语句超时，并在数据库饱和时限流/快速失败，不积累无限等待的虚拟线程。
- **Java 21 尚未包含 Java 24 的 JEP 491 改善**；`synchronized` 内阻塞、部分 native 调用仍可能 pin carrier。通过 JFR `jdk.VirtualThreadPinned`、必要的诊断启动参数检查 JDBC/Redisson/应用调用栈，不把“库支持 Java 21”当成“没有 pinning”。
- 不跨线程传递 Entity、`EntityManager`、Hibernate Session 或事务。异步任务只传不可变 ID/DTO，在接收线程重建授权与短事务；避免在事务内 `parallelStream`、`@Async` 或随意派生线程。自定义 ThreadLocal 只放最小请求上下文并 `finally` 清理，异步边界显式传递身份/trace，不能依赖自动继承。
- **当前设备验证轮询保持原协议，不为换框架改成长轮询。** 未来确需通知长轮询时用 MVC `DeferredResult` / Servlet Async；注册 timeout/error/completion 清理（必要时 `AsyncListener`），取消等待、定时器和订阅，设置有限等待时限/并发上限，不在等待期间持有 DB 连接或分布式锁。
- Servlet 无法保证静默断网立即被发现；需要短超时、有界资源和适用协议下的心跳/写失败检测共同兜底，不能只依赖“客户端断开回调”。验证取消、TCP 断开、代理超时和应用停机后，待处理请求/订阅数回落且没有遗留虚拟线程。

### 7.5 JPA / Hibernate 7、PostgreSQL 与事务

强制配置：`spring.jpa.open-in-view=false`；`spring.jpa.hibernate.ddl-auto=validate`（包括生产），禁止 `update/create/create-drop` 自动变更业务库；`spring.jpa.properties.hibernate.default_batch_fetch_size` 从 **32** 起压测，生产关闭 SQL 绑定参数/结果内容日志。Flyway 在受控发布步骤以独立迁移角色执行，运行角色没有 DDL 权限。

- 防 N+1 不能只依靠 batch fetch：列表优先 DTO projection、显式 fetch plan / EntityGraph，结合 SQL 数量断言；集合 fetch join 与分页分开处理，不开启任意 EAGER、不靠 OSIV 在响应序列化阶段补查询。
- 事务仅包数据库读改写；禁止在持有事务/连接时等 Redis 锁、用户输入、长轮询、SMTP 或远程 HTTP。锁等待、SRP 计算先完成，必要时在写事务内重验状态；异步邮件/通知通过提交后事件或事务 outbox 派发，不因事务回滚发出成功通知。
- `@Version` 用于需要并发修改的聚合；同步、撤销、恢复/凭据更改等必须以 PG 条件更新/唯一约束/必要行锁闭合竞态。乐观锁冲突明确映射既有冲突语义，计数并可见，不做无界重试或自动覆盖用户数据。
- **对“`@Version` 字段加索引”的校正：不一刀切建单列版本索引。** `WHERE id=? AND row_version=?` 通常已由主键定位；更新 B-tree 索引中的版本列会阻碍该更新成为 HOT、增加索引维护。先确保账户范围、主键、同步游标、业务唯一键索引，再用 `EXPLAIN (ANALYZE, BUFFERS)` 与 HOT/写放大数据决定是否确有版本复合索引需要。
- 监控/限制长事务、`idle in transaction`、锁等待、dead tuples 与 autovacuum；批处理分批提交，分页使用稳定游标，不在事务中遍历全部账户。连接池超时不替代 PG 的 `statement_timeout` / `lock_timeout` / `idle_in_transaction_session_timeout`，各自按路由预算设置。
- 同步游标必须保证提交可见性与 pull 分页不漏项；**不能直接把 `nextval()` 分配顺序当作事务提交顺序**。在 PG 中实现并验证账户范围内写入和游标推进的原子性/提交顺序（例如同一账户行锁串行化写事务），不能假定当前先读后写实现已具备这些保证；不凭 Redis 全局锁保证正确性。
- Java 实体时间使用 `Instant`；迁移先兼容现有 ISO-8601 TEXT 字段和既有 Rust 可读语义，再在回滚窗口后单独评审 `timestamptz` 变更，不把框架迁移与时间列重写绑成一次不可回滚操作。API 仍为 Unix 秒；针对旧 0001→0002 时间转换增加非 UTC 数据库会话测试，查明数据实际时区后再转换，不能仅看到末尾 Z 就假定历史值正确。
- **账户隔离不是重开 E9 组织功能。** 含用户数据的查询必须绑定认证得出的 account_id，不信任请求体中的所有者；PG 对适用表启用 RLS，运行角色不得是 superuser、表所有者或有 BYPASSRLS。审计/关联表也受同样范围约束，必要时使用 FORCE RLS。
- 事务内通过参数化 `set_config(..., true)` 设置账户上下文，事务结束自动清理，不能用跨连接复用的会话级 SET；无上下文默认拒绝。注册/按邮箱查找/恢复引导等尚无账户身份的入口需独立最小授权路径，不能给常规运行角色整体绕过 RLS。测试连接复用、原生 SQL、批处理及异步请求的串号风险。

### 7.6 Envers 的审计范围与归档

- **现有面向用户的安全审计日志与 Envers 修订历史是两套职责，不能互相替代。** 保留原审计 API 与事件语义，`item_versions` / `change_log` 也继续服务原有同步契约；Envers 只对确需追溯的低频账户/设备状态等非敏感元数据做字段白名单审计。
- 不对整个保险库条目表加全量 `@Audited`；同步密文、密码/恢复密钥相关字段、SRP verifier、Token、邮箱密文、设备验证凭据等不进入修订表。使用选择性 `@Audited` / `@NotAudited` 和实际表内容测试，避免关联实体意外将敏感字段带入历史。
- 修订记录包含最小 actor 标识、账户范围、UTC 时间与关联请求标识，不放邮箱、IP 明文、请求体或解密值。默认不审计乐观锁版本字段；同一事务的审计随业务一起提交/回滚，不宣传成异步、零成本写入。
- 对需要 Envers 历史的路径，禁止 JPQL/HQL bulk DML、native SQL、`deleteAllInBatch` 等绕过逐实体事件；确需批量迁移/清理时使用单独授权维护路径并写独立操作审计，不伪称 Envers 自动覆盖。通过“实体更新有 revision、失败事务无 revision、批量路径被阻断”测试验证。
- S0/S1 明确保留期、月写入量、索引容量、最大可接受写放大及归档责任人；S4 交付可执行的分批归档/恢复任务，并测试账户注销与法定保留边界。只写一句“以后清理”不算完成。
- 分区按容量预估触发：先核对 Envers 审计主键（实体 ID + REV）、修订关联、查询与所选审计策略；按时间分区时，PG 唯一键包含分区键的要求及跨表关系必须有验证方案，不直接给 `_AUD` 表加时间分区就上线。可先用有索引的普通审计表和小批量归档，迁移到分区的阈值、演练及数据核对必须先定。

### 7.7 Redis / Redisson 边界与分布式锁

- **Redis 中禁止保存保险库密码密文，更禁止密码明文。** 同样禁止同步条目密封盒、恢复包、邮箱密文、Secret Key、Vault Key、SRP 临时私值/会话秘密和原始 Bearer Token；Redis 不承担保险库存储、JPA 二级缓存或密钥缓存。
- Redis 承担会话元数据主存、入口限流、经白名单批准的非敏感业务缓存、通知唤醒及短期去重协调信息；各自使用独立命名空间、TTL及容量预算。只存 token 摘要而非原文；PG仍负责持久幂等结果/账本、设备权限/撤销代次和恢复凭据一次消费。Redis丢失或恢复旧快照不得复活已撤销会话，不能用缓存过期等待替代权限立即失效。
- 会话续期必须原子检查键仍存在、尚有效且代次匹配，只续期不重建；测试与 logout 的交错。注册/登录/恢复明确 Redis 签发与 PG 提交的先后、失败补偿和响应丢失行为；依赖故障返回安全、明确的系统错误，不能把已提交恢复误说成完全回滚。旧 sessions 只经受控一次迁入或显式作废，不作在线长期回源。
- 普通业务缓存使用有界、带抖动TTL的cache-aside或等价模式；只有可重建且不决定放行旧权限的数据可在缓存故障时回源。包含邮箱密文、密钥封装或条目blob的实体不得整体缓存。
- SRP challenge 继续使用 **PG 中的短期密封记录**，兼容现有 `handshakes.b_enc` 加密用途和 120 秒失效语义；解密的临时私值/会话秘密仅在当前请求内存短暂使用，不进 Redis。用 `DELETE ... RETURNING` 或等价短事务原子领取/消费挑战，不能保留“先 SELECT、再独立 DELETE”的重放窗口；过期记录有定期清理、容量/入口限流。这样多副本共享 PG 即可，不额外引入粘性路由；切流前排空/按受控策略作废在途挑战，实例失败后客户端重新开始握手。
- 只创建一个 RedissonClient；显式限定普通连接/订阅连接池、Netty/event-loop 线程、命令超时、重试和连接预算，不因请求线程虚拟化无限放大 Redis 连接。Redis 内网隔离、ACL、TLS、容量/淘汰策略与超时失败策略均进入部署配置。
- **需要分布式锁才引入锁**；使用有限 `waitTime` 与明确 `leaseTime` 的 `tryLock`，禁止无限等待或仅依赖 watchdog 的无上限业务持锁。持锁方法在同一线程完成业务和提交后，`finally` 检查持有者并释放；不能跨 MVC 异步线程拿锁/解锁。
- 固定 lease 到期后旧持有者可能继续运行；过期释放不等于业务已停止。关键写入必须使用 PG CAS/唯一约束、或能在存储端拒绝过期持有者的 fencing 机制；测试“租期到期后两个执行者同时写”的结果。Redis 锁不是同步游标、积分扣款或恢复一次性的唯一正确性保障。
- Redis 断连时认证/恢复等防滥用入口采用事先定义的拒绝或严格本机保守限流，不静默放开无限请求；通知可降级到既有轮询。不要把所有不依赖 Redis 的本地保险库能力一起阻断。

### 7.8 安全防护、AOP 与 HTTPS

- 建立受限 Repository 基类/写接口，禁止业务层调用无边界 `deleteAll`、`deleteAllInBatch` 及无有效条件的 update/delete。AOP 在应用写入口校验认证范围、非空业务条件和显式维护授权；缺少账户/ID/有效范围时默认拒绝。
- **AOP 不是 SQL 防火墙**：自调用、native SQL、JPQL bulk DML、数据库脚本可能绕开代理，`WHERE 1=1` 也不是有效边界。配合 ArchUnit、仓库接口白名单、代码审查、PG 最小权限/RLS与破坏性语句集成测试，不依赖字符串含 `WHERE` 就放行。账户级删除是单独的已授权用例，不能与无条件全库删除混为一谈。
- 日志采用字段白名单与集中脱敏兜底；禁止 HTTP body、Authorization、Cookie、SQL bind 参数、Entity/敏感 record 的自动 `toString()` 进入日志/异常/trace。包括反向代理、Hibernate、Redisson、邮件与 Actuator；生产禁止开发期邮件验证码明文日志。堆转储/JFR 等诊断产物受控保存并限时清理。
- 对外 **HTTPS 强制开启**，TLS 1.2/1.3、HSTS、证书续期/到期告警；客户端不以 HTTP 降级兜底。默认 Jetty 配置 TLS，可用 Boot SSL Bundles；若由入口终止 TLS，Jetty 必须限回环或受控私网且按部署要求保护内部链路，不允许公网直连 HTTP 后门。
- 只信任明确列出的反向代理：入口清除伪造 Forwarded / X-Forwarded-* 再写入真实值，应用只接受可信入口；验证 TLS 强制逻辑、URL 构造、客户端地址和限流键不能被伪造头绕过。不能只打开 `forward-headers-strategy` 就声称信任链完整。
- Spring Security 默认拒绝未知路径，公共注册/登录/恢复/健康检查显式列白名单；保护 Actuator 和运维端口。复用既有 Bearer 语义、不启用默认网页登录/HTTP Basic，不将业务身份存入容器 HttpSession；是否关闭 CSRF 必须依据接口实际仅用 Bearer、没有浏览器自动携带认证 Cookie 的前提。
- 统一请求大小、批量条目数、分页大小、序列化深度、SRP 输入长度与算法成本上限；禁止接受任意多态反序列化类型。认证与授权失败无敏感上下文泄露，登录/恢复引导保持既有诱饵与防枚举行为；注册仍返回既有 **409 / email_taken**，不能为了统一响应破坏旧客户端契约。注册枚举面的进一步收敛属于需单独设计客户端兼容策略的安全变更，不冒充已有能力。

### 7.9 可观测性与容量门禁

使用 Actuator + Micrometer，HTTP 服务、JDBC 与自定义业务指标统一关联 trace；不把 account_id、邮箱、token、item_id 等高基数字段作为指标标签。具体 meter 名称在所选版本实测，不编造一个“虚拟线程阻塞率”就算已监控。

| 必须观测 | 实施与验收重点 |
|---|---|
| Hikari | active/idle/pending/max、获取连接耗时 p95/p99、timeout 次数；并发超过连接预算时等待有界、连接不泄漏，不能只看连接总数 |
| PG / JPA | 事务时长、锁等待/死锁、慢查询、SQL 次数、乐观锁冲突及重试次数、HOT 比例、dead tuples/autovacuum；压测不能只在空库进行 |
| Jetty | 连接数、请求 in-flight、异步/长轮询数与超时/取消数、平台池忙闲/leased/排队；断开/超时后资源回收可验证 |
| Java 21 虚拟线程 | JFR `jdk.VirtualThreadPinned`、pin 持续时间与堆栈、请求/异步任务存活和等待量、载体 CPU；死锁/热点使用支持虚拟线程的诊断方式，不能依赖只统计平台线程的老指标 |
| Redisson / Redis | 命令时延、超时/失败、连接/订阅数、锁等待/租期超时、key/内存/驱逐；Redis 故障不应使 PG 写入绕过约束 |
| Envers | 每次业务写对应审计行数、事务耗时增量、表/索引增长、归档延迟、保留期违规与恢复验证；不要审计高频密文造成双倍存储 |

S0 记录硬件、PG 连接预算、数据规模和现有基线；S4 冻结可接受的吞吐、端到端 p95/p99、错误率、资源恢复窗口和告警阈值。评估虚拟线程收益以相同 DB 池/负载进行对比，不靠加连接“制造加速”。

- 切流只允许一个生产写入者。影子验证只做只读查询或脱敏样本在隔离环境重放，注册、登录 challenge、恢复、同步 push、发邮件等有副作用路径不能复制到真实影子服务。
- 停写时排空在途事务和握手，再备份并核对账户/设备/条目/审计计数、密文字节/哈希、游标和过期行为。server secret 等通过已有秘密管理渠道保持一致，绝不写进迁移日志或仓库。
- **回滚应用不等于恢复旧快照。** 若 Java 已接收新写入，优先在兼容 schema 上回切经过验证的旧实现；需要格式逆转换时须演练增量回灌并校验。只允许在尚无新写入且核实安全时恢复切流前快照，不能以“回滚”名义丢弃用户新数据。默认 P2 生产写入在服务端回滚窗口结束后启用。
- **RLS/角色也是需要回滚的数据库行为，不只是 schema。** 当前 Rust 不设置 Java 方案的事务级账户上下文，原样换回旧二进制会被“无上下文拒绝”策略阻断。S3 必须交付经审查的旧策略/权限恢复脚本或具备相同账户上下文机制的兼容回滚构建，选定路径在 S5 停写窗口演练；验证旧实现恢复后的认证、同步及跨账户拒绝，禁止临时授予 superuser/BYPASSRLS 兜底。未证明回滚后仍能正确隔离账户，不准启用生产 RLS 变更并切流。
- 在 S4/S5 更新 `docs/05`、部署文件与 CI，将 PostgreSQL/Redis/Java 的检查纳入门禁；保留当前 Caddy 入口及服务端口映射契约（现为 8787），替换应用镜像并新增 Redis，TLS 按 §7.8 验证。`docs/03` 记录密码学跨语言兼容证据而不是新发明算法；旧 Rust 服务端退出需另行变更 Cargo/镜像/CI，客户端 Rust 检查继续。
- 当前服务端 e2e 主要自启 SQLite，CI 的 PG 冒烟仅能证明迁移/配置检查，不能作为 PG 业务或并发正确性的证据。Java 必须补真实 PG/Redis/Jetty 与多副本集成测试；相关现状见 [e2e](../crates/vault-server/tests/e2e.rs:24)、[CI](../.github/workflows/ci.yml:26)、[部署](../deploy/docker-compose.yml:5)。

### 7.11 风险验收清单（未完成，不代表已测试）

- [ ] 依赖树与实际进程确认 Java 21 / Boot 4 稳定版 / Jetty / Hibernate 7 + 同版 Envers / 单一 Redisson，无 Tomcat、Lettuce 或 Jedis；精确版本与 digest 可重现。
- [ ] 原 Rust/Flutter 客户端对 Java 完成注册、登录、设备验证/撤销、同步、改密码、恢复、退出和注销；JSON 黄金样本、SRP/AES/HMAC 交叉向量与所有协议错误码一致。
- [ ] OSIV 关闭、Flyway 管 schema；SQL 数量测试阻断 N+1；有限 Hikari 池和事务超时生效；没有 Entity/Session/事务跨异步线程。
- [ ] 并发 push、同条目更新、恢复重复消费、凭据轮换/设备撤销竞态、事务乱序提交/回滚与稳定游标分页均不漏数据、不越权。
- [ ] 虚拟线程超过 DB 容量时没有无限堆积；JFR 检查 Java 21 pinning；客户端断开/代理超时/取消/停机后 Jetty 长连接、订阅、线程和连接均按预算回收。
- [ ] Envers 只留白名单字段，业务回滚无修订残留，敏感列未进入审计；危险批量 DML 被拒；审计增长、归档、恢复和账户删除演练通过。
- [ ] Redis 无保险库密文/秘密；Redis 清空/故障切换、锁租期过期及旧持有者继续写不会破坏 PG 约束；未无限续租或跨线程解锁。
- [ ] 无条件/伪条件 update/delete、账户 ID 伪造、RLS 空上下文/连接复用、native SQL 与 AOP 自调用绕过均有测试；合法账户级删除不被误当全库操作。
- [ ] 日志/trace/异常/邮件/SQL 参数抽查无敏感值；真实 TLS、受控代理转发、Actuator 隔离、请求体与密码学计算限额通过，不靠 MockMvc 代替网络行为。
- [ ] Java 的 Maven `verify`、Testcontainers PG/Redis、真实 Jetty 网络测试、既有 Rust/Dart/扩展回归及 CI 均有实际报告；新旧库升级、备份还原、切流后新增数据回滚无损。
